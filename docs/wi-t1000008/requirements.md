# 轻量库存管理应用 · 需求基线

> Work Item：wi-t1000008 ｜ 阶段：requirements ｜ 应用形态：React 前端应用，数据使用本地状态管理（用户明确提出）

来源标注约定：**[用户]** = 用户明确提出；**[推荐]** = 为闭合核心目标必需的最小推荐基线；**[未规定]** = 用户未提出且不影响核心验收，本稿不作规定。

## 1. 目标

用户明确提出开发一个"轻量库存管理"React 应用，核心目标：

1. 以物料列表管理库存物料，展示编码、名称、分类、当前库存、安全库存；
2. 支持搜索与低库存筛选，快速定位物料；
3. 提供入库、出库登记，提交后自动更新库存并生成库存流水；
4. 首页汇总展示物料总数、库存总量、预警数量；
5. 数据使用本地状态管理，不依赖后端服务。

## 2. 核心行为与规则

### 2.1 物料与物料列表 **[用户]**

- 物料字段：编码、名称、分类、当前库存、安全库存。
- 物料列表以上述五个字段展示全部物料。

### 2.2 新增物料 **[推荐]**

- 用户未提出物料来源。为使列表与出入库登记存在可操作对象（闭合核心目标的必要缺口），推荐支持新增物料：录入编码、名称、分类、安全库存、初始当前库存后加入列表。
- 编码唯一标识一个物料（重复编码的提交被拒绝并提示）**[推荐]**。

### 2.3 搜索与低库存筛选 **[用户]**

- 列表支持关键词搜索 **[用户]**；搜索匹配编码、名称、分类三个字段 **[推荐]**。
- 列表支持"低库存筛选"，只显示当前库存低于安全库存的物料 **[用户]**。
- 低库存判定口径：当前库存 < 安全库存 **[推荐]**；"等于安全库存"是否算低库存 **[未规定]**。

### 2.4 入库 / 出库登记 **[用户]**

- 提供入库、出库两类登记表单 **[用户]**。
- 表单最小字段：选择物料、填写数量 **[推荐]**；操作人、备注、日期等字段 **[未规定]**。
- 数量为正整数 **[推荐]**。
- 入库：提交后该物料当前库存增加相应数量 **[用户：提交后自动更新库存]**。
- 出库：提交后该物料当前库存减少相应数量 **[用户]**。
- 出库数量超过该物料当前库存时，阻止本次出库并给出明确提示；当前库存不变、不生成流水 **[推荐：安全、可逆]**。
- 负库存是否允许出现：**[未规定]**（按上一条推荐基线，正常流程不产生负库存）。

### 2.5 库存流水 **[用户]**

- 每次入库、出库成功后生成一条库存流水 **[用户]**。
- 流水记录字段：类型（入库/出库）、物料、数量、发生时间 **[推荐]**。
- 流水可在应用内查看 **[推荐：生成结果必须可观察]**；流水展示位置（列表同页或独立区域）**[未规定]**。

### 2.6 首页统计 **[用户]**

- 首页展示物料总数、库存总量、预警数量 **[用户]**。
- 计算口径 **[推荐]**：物料总数 = 物料条目数量；库存总量 = 全部物料当前库存之和；预警数量 = 低库存物料数量（口径同 2.3）。
- 三个数值随物料与库存变动实时保持一致 **[推荐]**。

### 2.7 数据与边界

- 数据使用本地状态管理 **[用户]**：刷新页面或重开后的数据保留情况 **[未规定]**，不作为验收要求。
- 物料的编辑、删除、导入导出、多仓库、审批流等能力用户未提出，不纳入本次基线。
- 页面数量与布局 **[未规定]**：单页或多页组织均可，以各 AC 的入口可达为准。

## 3. 验收场景

### AC-01：首页展示物料总数、库存总量与预警数量

- 验收条件：首页以三个独立数值分别展示物料总数、库存总量、预警数量，口径正确且随数据变动同步更新。
- 入口类型：用户界面
- 验证动作：在已存在若干物料（其中至少一个当前库存低于安全库存）时打开首页，记录三个数值；新增一个物料，再通过一次出库使另一物料当前库存降至安全库存以下，再次查看首页。
- 预期结果：物料总数等于物料条目数量；库存总量等于各物料当前库存之和；预警数量等于当前库存低于安全库存的物料数；上述变更后三个数值同步变为正确值。
- 证据类型：runtime-render

### AC-02：物料列表展示物料并支持新增物料

- 验收条件：物料列表展示全部物料的编码、名称、分类、当前库存、安全库存；新增物料成功后立即出现在列表中。
- 入口类型：用户界面
- 验证动作：打开物料列表，逐字段核对已有物料的展示；通过新增物料入口录入编码、名称、分类、安全库存与初始当前库存并提交；再用一个已存在的编码重复提交。
- 预期结果：列表逐行展示五个字段且与数据一致；新物料提交后出现在列表中，各字段值正确；重复编码被拒绝并给出提示，列表不出现重复条目。
- 证据类型：runtime-render, interaction

### AC-03：搜索与低库存筛选

- 验收条件：物料列表支持按关键词搜索，并支持只查看低库存物料。
- 入口类型：用户界面
- 验证动作：在搜索输入中输入某物料编码（或名称、分类）的关键词；清除搜索后启用低库存筛选；再取消筛选。
- 预期结果：搜索后列表仅显示匹配该关键词的物料；低库存筛选后列表仅显示当前库存低于安全库存的物料；取消筛选后恢复显示全部物料。
- 证据类型：interaction

### AC-04：入库登记后当前库存增加并生成入库流水

- 验收条件：选择物料并提交入库数量后，该物料当前库存增加，同时生成一条入库流水。
- 入口类型：用户界面
- 验证动作：记录某物料当前库存原值；在入库登记中选择该物料、填写数量并提交；查看该物料的当前库存与库存流水。
- 预期结果：该物料当前库存 = 原值 + 入库数量；库存流水中新增一条类型为"入库"的记录，包含该物料、入库数量与发生时间。
- 证据类型：interaction

### AC-05：出库登记后当前库存减少；库存不足时阻止出库

- 验收条件：出库提交后当前库存减少并生成出库流水；出库数量超过当前库存时操作被阻止，库存与流水均不变。
- 入口类型：用户界面
- 验证动作：记录某物料当前库存原值；在出库登记中选择该物料、填写不超过当前库存的数量并提交，查看库存与流水；再填写一个超过当前库存的数量提交。
- 预期结果：正常出库后当前库存 = 原值 − 出库数量，流水新增一条类型为"出库"的记录（含物料、数量、时间）；超量提交被阻止并出现明确提示，当前库存保持原值且不产生新流水。
- 证据类型：interaction, error-feedback

### AC-06：库存流水可查看

- 验收条件：应用内可查看库存流水，每条流水包含类型、物料、数量、发生时间。
- 入口类型：用户界面
- 验证动作：先后完成至少一次入库和一次出库后，打开库存流水的查看入口。
- 预期结果：能看到对应的入库与出库流水记录，四个字段完整，物料与数量与实际登记一致。
- 证据类型：runtime-render

## 4. 需求闭合核对

- 用户明确提出的核心目标（物料列表五字段、搜索、低库存筛选、入库/出库登记、自动更新库存、库存流水、首页三项统计、本地状态管理）均有对应行为规则与可观察验收（AC-01 ~ AC-06）。
- 推荐基线仅用于闭合必要缺口：物料来源（新增物料）、搜索匹配范围、低库存/统计口径、表单最小字段、出库超量阻止、流水可查看；均已标注且可在后续阶段按用户决定调整。
- 未臆造角色、权限体系、部署方式、持久化方案或技术选型；React 与本地状态管理为用户明确提出。
