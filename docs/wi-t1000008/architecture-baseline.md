# 轻量库存管理应用 · 架构基线

> Work Item：wi-t1000008 ｜ 阶段：design（simple-frontend 精简路线）｜ 需求基线：docs/wi-t1000008/requirements.md（sha256:e4bb3cabb3653e5b319124d17cb622a28e6f986c823f0f0b4cedab3a1b4a5eb5）

## 1. 应用形态

单用户 React/Vite 单页应用（SPA），全部业务逻辑与数据由前端承载。无服务端、无数据库、无认证、无后台任务、无外部集成。需求基线明确"数据使用本地状态管理，不依赖后端服务"，本设计不扩展、不重裁产品语义。

## 2. 页面与交互范围

按需求基线核心目标组织以下界面区域（页面数量与布局需求未规定，以各验收条件的入口可达为准）：

- **首页统计**：展示物料总数、库存总量、预警数量三个独立数值。三个数值均由物料数据实时派生，不单独存储，随物料与库存变动同步更新。
- **物料列表**：展示全部物料的编码、名称、分类、当前库存、安全库存；支持关键词搜索（匹配编码、名称、分类）与低库存筛选（仅显示当前库存低于安全库存的物料），两者可叠加；提供新增物料入口（录入编码、名称、分类、安全库存、初始当前库存）。
- **出入库登记**：入库、出库两类表单，最小字段为选择物料与填写数量（正整数）。提交成功后自动更新对应物料当前库存并生成库存流水。
- **库存流水**：应用内查看出入库流水，每条含类型（入库/出库）、物料、数量、发生时间。

## 3. 数据归属与浏览器状态

- 全部业务数据（物料、库存流水）保存在浏览器 `localStorage`。应用提供单一读写边界（状态管理层）：界面不直接读写存储，统一经该层读取与提交，保证列表、统计、流水三处视图数据一致。
- 数据在同一浏览器配置文件中刷新或重新打开后仍保留；不实现也不承诺跨浏览器、跨设备、跨用户共享。
- 需求基线对"刷新/重开后数据保留"未作验收要求；持久化仅是不改变验收语义的附加能力，不作为验收条件。

## 4. 核心数据形状与校验边界

仅说明解释设计所必需的最小形状，不复制需求规则：

- 物料：编码（唯一）、名称、分类、当前库存、安全库存。
- 流水：类型（入库/出库）、物料、数量、发生时间。

校验集中在读写边界处执行：编码唯一（重复提交被拒绝并提示）、数量为正整数、出库数量不得超过当前库存（超量阻止并提示，库存与流水均不变）。一次成功的出入库在同一读写边界内完成两件事：更新物料当前库存、追加一条流水，保证库存与流水始终一致。

## 5. 实现入口与运行方式

- 新建 React/Vite SPA，源码位于本工作区内；实现阶段以 Vite 开发服务器运行（依赖就绪后使用 `npm run dev`），通过其输出的本地地址在浏览器中验证。
- 本阶段不虚构具体文件路径清单；实现阶段按上述界面区域落地组件与状态读写边界。
